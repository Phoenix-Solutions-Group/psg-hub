## Workflow

1. Search the BSM project for duplicates before creating an issue.
2. Create issues only in the existing BSM project and its attached team.
3. Use the team's existing default status.
4. Leave issues unassigned unless an assignee is explicitly requested.
5. Reuse existing statuses and labels; do not create replacement teams, projects, statuses, or duplicate labels.
6. Read and update issues by Linear identifier or by searching within the BSM project.
7. Preserve fields outside the requested change.

Use an authenticated Linear integration. If Linear access is unavailable, report the authentication blocker instead of silently falling back to GitHub Issues or local markdown.
